# 拼布对决 · Patchwork

参照“卡坦岛”的制作方式重新设计的双人拼布策略游戏：深色桌面、原创 SVG 织物、沿布料真实轮廓的缝线与放置预览。界面以笔记本一屏棋桌为目标，同时适配手机；支持人机练习、同屏双人、独立交互教学和开房联机。

## 启动与试玩

[公开试玩（人机 / 同屏双人）](https://origin-zxy.github.io/Patchwork/) · [云端联机大厅](https://patchwork-stitch-table.zsj2957310036.chatgpt.site/?online=1)。GitHub Pages 中的联机入口会进入云端棋桌；房主创建房间后，把邀请链接或 6 位房间码发给有站点访问权限的朋友，即可加入并开始对局。

安装 **Node.js 22.13 或更高版本**，在项目目录运行：

```sh
npm start
```

项目没有第三方运行依赖，无需先运行 `npm install`。打开终端显示的地址，默认是 **http://127.0.0.1:4174**。页面使用 ES Modules，请通过 HTTP 服务访问。

- 默认进入人机练习；“开始新局”可以选择同屏双人，以及 AI 的轻松（easy）、标准（normal）、挑战（hard）难度。
- 选中可购买布料，点击棋盘选位置，再点击“缝在这里”；在同一位置再次点击也可确认。
- `R` 旋转，`F` 翻转，`Esc` 取消选择。手机可使用对应按钮。
- 双方拼布板等大显示，点击对手拼布板可进一步放大查看。
- 桌面和平板棋桌按窗口高度分配空间，双方棋盘、时间轴、市场与操作按钮可在同一屏幕查看；全部布料、日志和规则通过弹窗展开。
- 布料市场可横向浏览，每块直接显示费用、耗时和收入；“查看全部”展示整圈布料，仍然只有顺序最前的三块可以购买。
- “新手教学”会带你实际选布、旋转、选位置、确认和前进，使用独立棋局；退出后恢复原局。
- 人机和同屏进度自动保存在此浏览器的 `localStorage`，刷新后继续。开始新局会替换练习存档。

默认端口为 `4174`，监听地址为 `0.0.0.0`；需要时可通过 `PORT`、`HOST` 环境变量调整。

## 两个人联机

1. 房主启动服务。处于同一局域网的两台设备，打开终端显示的局域网地址，例如 `http://电脑的局域网IP:4174`。
2. 房主进入“联机大厅”，填写名字，点击“创建房间”。
3. 朋友通过邀请链接或 6 位房间码加入，房主点击“开始对局”。
4. 各自在自己的窗口操作自己的拼布板，合法行动由服务端确认并同步。

要分享给手机或另一台电脑，房主也应先用局域网地址打开页面再创建房间，复制出的邀请链接才包含朋友可访问的地址。仅在自己的电脑试玩时，可以新建两个空白窗口，分别打开同一个服务地址，模拟双方入座。

联机座位凭证保存在各自窗口的 `sessionStorage` 中，刷新原窗口可恢复。复制已经入座的标签页可能复制同一座位；模拟第二位玩家时请新建空白窗口再输入地址。关闭窗口或清除浏览器数据会丢失该窗口的座位凭证。

本地服务使用 **HTTP + SSE** 同步，并以轮询辅助恢复连接。房间和棋局自动保存到 `.patchwork-rooms/`；保留此目录并重启服务后，原窗口可重新连接。可通过 `PATCHWORK_ROOM_DIR` 指定其他保存目录。该目录已加入 Git 忽略规则。

## 玩法

- 每人持有 5 枚纽扣和一张 9 × 9 拼布板。33 块常规布料构成环形市场，只能购买中立标记之后的三块之一。
- 时间轴上落后的人行动；时间相同，刚到达该格的人行动。因此可能连续行动多次。
- 可以购买、旋转或翻转布料，放入自己的拼布板后支付纽扣、增加收入并推进时间；布料不能重叠或越界。
- 也可以选择“前进，领取纽扣”，移动到对手前一格，每实际前进一格获得一枚纽扣。到达终点时只计算实际移动距离。
- 经过收入点，按已放布料的纽扣收入获得纽扣。率先经过皮革标记的人拿走对应 1 × 1 补丁，必须先放完获得的补丁；棋盘已满时自动弃置无法放置的补丁。
- 首位填满任意 7 × 7 区域的玩家获得一次 7 分奖励。
- 双方都到达时间轴终点 53 后结算：**剩余纽扣 + 7 × 7 奖励 − 空格数 × 2**。同分时，先到达终点的人获胜。

本项目的 **33 块常规布料**采用 Patchwork 经典版的形状、纽扣费用、耗时和收入。每块带有可追溯的 `classicId`，参考来源、逐块对照及独立校验方法见 [经典版布料数据](docs/classic-patches.md)。中文名称、颜色与织物图案为原创。时间轴按经典版及官方 2017 年皮革补丁勘误校准：收入在进入第 `5、11、17、23、29、35、41、47、53` 格时触发，皮革补丁位于第 `26、32、38、44、50` 格（起点计为 0）。棋盘有拼布面、素色面两种外观，支持随时切换、记住偏好和放大查看；两面共用相同规则，切换保留所有对局进度。完整来源及触发约定见 [经典版时间棋盘](docs/classic-time-board.md)。

本地当前存档使用独立键 `patchwork-table-classic-v2`。上一版经典布料存档 `patchwork-table-classic-v1` 在双方都未到达第 20 格、未领取旧皮革时可保留进度升级；否则保留旧存档并开始新局。更早的 `patchwork-table-v2` 也原样保留。旧版已开局联机房间提示创建新房间，避免混用事件规则。

## 公网部署与构建

旧版 Supabase 配置和依赖已移除。不同部署方式的能力如下：

| 部署方式 | 人机 / 同屏 | 跨设备联机 |
| --- | --- | --- |
| 本仓库的 GitHub Pages | 支持 | 联机入口自动进入已部署的云端棋桌 |
| 自行部署到其他静态托管 | 支持 | 需另行提供联机服务 |
| `npm start` 的 Node 服务 | 支持 | 支持，设备需能访问该服务地址 |
| Cloudflare Worker + D1 | 支持 | 支持公网开房、加入与断线恢复 |

构建云端版本：

```sh
npm run build
```

构建输出为 `dist/server/index.js`，其中包含 Worker 和前端静态资源。部署时需要绑定名为 `DB` 的 Cloudflare D1 数据库，并执行 `db/schema.sql` 初始化表结构。Worker 使用服务端规则校验、版本校验和 D1 持久化；浏览器约每两秒拉取房间更新。云端不依赖本地 Node 进程持续在线。

`npm run build` 只生成构建产物，不会自动上传或发布到 GitHub。

## 验证与代码入口

```sh
npm test
```

测试覆盖规则与计分、AI 完整自弈、房间权限与同步，以及服务端和云端接口。主要代码：

- `engine.js` / `ai.js`：浏览器与服务端共用的规则和 AI。
- `app.js` / `art.js` / `styles.css`：界面、教学、原创 SVG 与响应式布局。
- `room-client.js` / `server/`：联机客户端、本地房间与 HTTP/SSE 服务。
- `worker/` / `db/` / `scripts/build-cloud.mjs`：云端联机、数据库与构建脚本。
